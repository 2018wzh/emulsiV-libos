# 架构、所有权与平台约束

## 分层

应用直接调用 libOS API，不经过 ECALL。GPIO/TextIO/Bitmap 通过 `RegisterIo` trait
访问 MMIO；主机回归测试用模拟总线替换真实地址访问。图形算法接受 `PixelTarget`，
因此可以画到 framebuffer 或 MonoBuffer。逻辑工具不依赖硬件，也不依赖堆。

这是一套可组合的 library OS / BSP / runtime，不提供进程、文件系统、网络、页表、
SBI、POSIX 系统调用或抢占式线程。没有真实时间来源，因此不提供名为 `sleep_ms`
却实际执行空循环的接口。

## 启动与中断

复位地址 0 和中断地址 4 各放一条 4 字节 JAL x0。启动设置 gp 和 16 字节对齐的 sp，
关闭两个已知设备中断源，清零 BSS，再进入 `__libos_main`。
`.data` 在 RAM 中原位加载，无 ROM 拷贝过程。仅跳回 reset 入口不会恢复已修改的 `.data`；
需要恢复初始数据时必须重新加载 HEX，不能把热跳转当作完整冷启动。

中断入口为普通 Rust C ABI 回调保存 ra、t0..t6、a0..a7，总共 64 字节。
Rust 编译器负责回调自身的 s0..s11 保存。sp、gp、tp 必须按 ABI 使用。
Virgule 的简化中断模型在 MRET 前禁止嵌套；返回使用 MRET，不读写 CSR。

默认回调关闭中断源，避免未处理的电平请求导致中断风暴。`interrupt!` 定义强符号回调。
链接脚本用 `PROVIDE` 选择默认处理器；不能对尚未定义的外部函数使用汇编 `.set` 别名，
否则汇编器可能直接把调用重写到默认函数，导致用户回调无法覆盖。
本项目包含专门的强符号覆盖回归测试。

## MMIO 与共享状态

`Mmio::new()` 是 unsafe，因为地址有效性由调用者和平台共同保证。
句柄不实现 Send/Sync；读写使用 volatile，GPIO 寄存器要求 32 位对齐。
普通安全驱动方法只访问受限地址，Bitmap 的内存区域不属于 Rust 分配对象。

volatile 不等于原子，也不是线程同步工具。多句柄的 GPIO 读改写可能被 IRQ 打断。
`with_device_irqs_masked` 只屏蔽两个已知外围中断源，不是架构级 CSR 临界区。
输入硬件仍会变化，IRQ 屏蔽也不能补回设备没有记录的事件。

Queue、EventQueue、Scheduler 和 LineEditor 都要求单一所有者。它们不是可以直接放入
`static mut` 并在主程序/IRQ 同时调用的共享容器。本项目中断示例避免共享可变 Rust 对象。
跨中断事件传递必须额外设计正确的同步协议，而不能添加几个 volatile 就宣布线程安全。

## 输入事件的真实限制

TextIO 只有一个字节的数据锁存器。软件环形队列不能让硬件变成 FIFO；字符到达过快仍可能覆盖。
GPIO 上升沿和下降沿寄存器也是锁存位，不记录同一位的发生次数。
GPIO 事件位是普通可写位。`clear_edges(mask)` 通过读改写保留未选中的旧事件，
`clear_all_edges()` 写 0。读改写期间的新事件可能丢失，接口不承诺无损捕获。

## 内存预算

默认 3072 字节普通 RAM 同时容纳指令、常量、数据、BSS 和栈。
链接器预留 512 字节栈，因此普通静态镜像最大到 0xA00。
Framebuffer 1024 字节在 0xC00 之后独立保留，不能拿来扩张默认程序空间。

链接断言只证明静态布局不重叠。它不能证明 Rust 应用运行时的栈峰值小于 512 字节。
中断的额外 64 字节、回调局部对象、格式化栈开销都必须计算。
`stack_remaining` 是即时读数，不是峰值测量，更不是硬件保护。
MonoBuffer 固定占 128 字节；不要误以为另一个 1024 字节全彩缓冲可以免费放入栈。

Arena 在借用的字节数组里分配对齐、清零且不重叠的片段。它不是全局 allocator，
没有自由释放/重置接口，也不能支持任意 `Vec`、`Box` 或 `String`。

## 时间与任务

所有 tick 由调用者推进，具有 u32 回绕语义。比较要求相关时刻相隔小于 2^31 tick。
调度器每轮最多执行给定数量的回调，每个任务最多执行一次，并合并漏过周期。
回调执行时间没有上界保障；阻塞回调仍会阻塞整个协作调度器。
任务编号有 generation 校验，但 generation 在 2^32 次注册后回绕。

## 参考执行器的范围

Python CPU 实现所需 RV32I 指令和 Virgule 的固定向量/MRET 行为，严格拒绝不支持的指令。
它不是上游代码的副本，也没有经过完整 RISC-V 合规测试。
通过该执行器是软件层测试证据，不等于浏览器 emulsiV 集成验证或真实硬件认证。
